### switch表达式
旧式switch
```
// ① 语句（Statement），不是表达式（不能赋值）
// ② 容易忘记 break → 穿透（fall-through）
// ③ 变量作用域混乱
// ④ 每个 case 无法返回值

// ❌ 旧式问题：
int day = 3;
String type;
switch (day) {
    case 1:
    case 2:
    case 3:
        type = "工作日";
        break;              // 忘了 break 会穿透！
    case 6:
    case 7:
        type = "周末";
        break;
    default:
        type = "无效";
}
```
新式switch（12预览，14正式）
```
// ✅ ① 箭头语法（没有穿透问题）
String type = switch (day) {
    case 1, 2, 3 -> "工作日";      // 多值合并
    case 6, 7 -> "周末";
    default -> "无效";
};
// switch 变成"表达式"，可以直接赋值！

// ✅ ② yield 返回值（复杂逻辑）
String type2 = switch (day) {
    case 1, 2, 3 -> {
        // 复杂逻辑用 yield 返回
        if (day == 1) yield "周一";
        else yield "工作日";
    }
    default -> "无效";
};

// ✅ ③ 没有 break、没有穿透
// 箭头后面的代码自动结束，不会 fall-through
```
新旧对比

|对比|旧 switch|新 switch|
|---|---|---|
|**性质**|语句|表达式（可赋值）|
|**穿透**|容易（break 忘写）|无（箭头自动）|
|**返回值**|手动变量|yield/箭头直接返回|
|**多值**|叠 case|case 1, 2, 3|
|**简洁性**|繁琐|简洁|
### Records（记录类型）
```
// Records（Java 14 预览，16 正式）：
// 一行代码定义"不可变数据载体"
// 自动生成：构造器、getter、equals、hashCode、toString
```
对比Lombok/手写
```
// ❌ 手写：几十行模板代码
public final class User {
    private final String name;
    private final int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public int getAge() { return age; }

    @Override
    public boolean equals(Object o) { ... }
    @Override
    public int hashCode() { ... }
    @Override
    public String toString() { ... }
}

// ✅ Records：一行搞定
public record User(String name, int age) {}
```
Records自动生成
```
public record User(String name, int age) {
    // 自动生成：
    // ① 构造器：User(String name, int age)
    // ② getter：name()、age()（注意不是 getName()）
    // ③ equals()、hashCode()、toString()
}

// 使用：
User user = new User("张三", 25);
user.name();        // "张三"（getter 是 name()，不是 getName()）
user.age();         // 25
user.toString();    // User[name=张三, age=25]
```
Records特性
```
// ① 不可变
// 所有字段都是 final
// 没有 setter

// ② 可以加额外方法
public record User(String name, int age) {
    // 额外方法
    public boolean isAdult() {
        return age >= 18;
    }

    // 校验（紧凑构造器）
    public User {
        if (age < 0) {
            throw new IllegalArgumentException("年龄不能为负");
        }
    }

    // 静态方法
    public static User of(String name, int age) {
        return new User(name, age);
    }
}

// ③ 可以实现接口
public record User(String name, int age) implements Serializable {}

// ④ 不能继承其他类（隐式 final）
// ⑤ 不能定义实例字段（只能有组件）
// ⑥ 不能声明为 abstract
```
对比Lombok的 @Data

|对比|Lombok @Data|Record|
|---|---|---|
|**可变性**|默认可变|不可变 ✅|
|**代码生成**|编译期字节码修改|JVM 原生|
|**依赖**|需要 Lombok 插件|JDK 自带|
|**继承**|可以|不能|
|**适用**|实体类、DTO|值对象、DTO|
什么时候用Record
```
// ✅ 适用：
// ① DTO（数据传输对象）
// ② 值对象（Value Object）
// ③ API 响应体
// ④ 配置项

// ❌ 不适用：
// ① JPA 实体（需要无参构造器 + 可变）
// ② 需要继承的类
// ③ 需要额外实例字段的类
```
### 面试高频

> **Q:** "Record 和普通类的区别？" 
> **A:** "Record 是一行代码定义不可变数据载体，自动生成构造器、getter（字段名()）、equals、hashCode、toString。字段全部 final，没有 setter。适合 DTO 和值对象，不适合需要继承或可变实体的场景。"
### Pattern Matching（模式匹配）
instanceof增强（14预览，16正式）
```
// ❌ 旧写法：先判断再强转
if (obj instanceof String) {
    String s = (String) obj;     // 强转
    System.out.println(s.length());
}

// ✅ 新写法：直接绑定变量
if (obj instanceof String s) {    // 模式匹配：直接绑定
    System.out.println(s.length());  // 不用强转
}

// 复杂条件：
if (obj instanceof String s && s.length() > 3) {
    System.out.println("长字符串: " + s);
}
```
变量绑定规则
```
// 绑定变量的作用域：
Object obj = "hello";

// ✅ 匹配成功，绑定变量 s
if (obj instanceof String s) {
    // s 可用
}

// ✅ 条件中的绑定
if (obj instanceof String s && s.length() > 5) {
    // s 可用
}

// ❌ 不能用 ||（无法保证 s 绑定）
// if (obj instanceof String s || ...)  // ❌ 编译错误
```
### NPE精准提示（14）
之前NPE疼点
```
// ❌ 旧版本：NPE 信息模糊
// Exception in thread "main" java.lang.NullPointerException
//   at com.example.Demo.main(Demo.java:10)
// 只知道第 10 行，不知道哪个变量是 null！

// 排查要打断点/猜
```
精准提示
```
// ✅ Java 14+（-XX:+ShowCodeDetailsInExceptionMessages 默认开启）：
// Exception in thread "main" java.lang.NullPointerException:
//   Cannot invoke "String.length()" because "user.name" is null
//   at com.example.Demo.main(Demo.java:10)
// 直接告诉你：user.name 是 null！

// 帮助定位：
User user = null;
System.out.println(user.name.length());
// NPE: Cannot read field "name" because "user" is null

// 本质：
// JVM 在字节码中注入细节（OmitStackTraceInFastThrow 的优化）
// 只对"同一位置的重复 NPE"有优化影响，可配置
```
