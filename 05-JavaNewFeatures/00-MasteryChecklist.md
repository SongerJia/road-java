## 1. Lambda 底层是怎么实现的？

**锚点**：javadoc / `invokedynamic` 字节码 / 《Java 8 实战》

- [ ] **及格**：Lambda 是**函数式接口**（只有一个抽象方法）的实例；语法 `参数 -> 方法体`；四大内置函数式接口（Predicate/Consumer/Function/Supplier）
- [ ] **良好**：及格 + 能解释底层——通过 **`invokedynamic` + LambdaMetafactory** 生成，**不产生额外的匿名类文件**；捕获的局部变量必须 **effectively final**；方法引用是 Lambda 的简写（四种形式：静态/实例/任意对象/构造器）
- [ ] **精通**：良好 + 能应对追问——Lambda 与**匿名内部类**的区别（是否持 this 引用、是否生成 class 文件、性能差异）、为什么捕获变量要 effectively final（变量在堆上，被捕获的副本需不变）、`@FunctionalInterface` 的作用（编译期校验）

## 2. Stream 中间操作为什么惰性（懒执行）？

**锚点**：`Stream.java` 源码 / 《Java 8 实战》第 4-5 章

- [ ] **及格**：Stream 三步——创建 → 中间操作（filter/map/sorted）→ 终止操作（collect/forEach/count）；**中间操作不执行**，只有终止操作才触发计算；Stream **只能用一次**
- [ ] **良好**：及格 + 能解释惰性的**好处**——① 短路（如 `limit`/`findFirst` 不用处理全部元素）② 一次遍历完成所有中间操作（管道化，而非每步一次循环）+ 有状态操作（sorted/distinct）与无状态操作（filter/map）的区别
- [ ] **精通**：良好 + 能应对追问——**并行流底层**（共享 ForkJoinPool commonPool，线程数默认 CPU 核数 - 1）、并行流的**性能陷阱**（数据量小反而慢、有状态操作有额外开销）、Stream 与 for 循环的性能对比、`peek` 的坑（中间操作不触发）

## 3. Java 8 / 11 / 17 / 21 各自的核心特性？

**锚点**：Oracle 官方 release notes / JEP

- [ ] **及格**：能说出各版本代表特性——8（Lambda/Stream/Optional/新日期 API/接口 default+static）、11（`var` 局部变量类型推断、`String.isBlank/strip`）、17（sealed class、switch 表达式、**LTS**）、21（**虚拟线程**、record pattern、**LTS**）

## 4. Optional 的正确使用姿势？

**锚点**：《Java 8 实战》第 10 章 / 官方 javadoc

- [ ] **及格**：Optional 用于显式表达「可能为空」，避免 NPE；常用方法——`of`（非空）/`ofNullable`（可空）/`empty`、`isPresent`、`orElse`/`orElseGet`/`orElseThrow`、`map`/`flatMap`/`ifPresent`
- [ ] **良好**：及格 + 能说出**正确用法**——只做**返回值**用（表示可能无结果）；`map`/`ifPresent` 链式处理，避免嵌套判空；`orElseGet`（延迟计算）vs `orElse`（立即求值）的区别
- [ ] **精通**：良好 + 能应对追问——**禁止用法**：不要做字段/方法参数、不要 `Optional.of(x).get()`、不要对 Optional 做 `==` 判断、不要在调用链中间用复杂逻辑；`ifPresentOrElse`（Java 9+）；为什么 `orElseGet` 比 `orElse` 省性能（空值时才调用 Supplier）
