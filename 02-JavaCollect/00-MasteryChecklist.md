## 2. 为什么树化阈值是 8？

**锚点**：`HashMap.java` 源码注释（泊松分布表）/ `TREEIFY_THRESHOLD`

- [ ] **及格**：说出阈值——链表长度 ≥ 8 触发树化（需数组 ≥ 64），退化阈值是 6
- [ ] **良好**：及格 + 能解释 8 的来源——官方注释给出的**泊松分布**：理想随机哈希下，链表长度达到 8 的概率约 0.00000006（千万分之六），正常几乎不会触发；树化是为了防**恶意哈希攻击**（所有 key 同 hash 导致 O(n) 退化）
- [ ] **精通**：良好 + 能应对追问——**为什么退化阈值是 6 而不是 8**（留 2 的缓冲，防链表长度在 8 附近震荡导致频繁树化/退化）、为什么数组长度要 ≥ 64 才允许树化（树化代价高，桶太少时扩容更划算）、红黑树 5 条性质

## 4. ConcurrentHashMap 1.8 为什么不用分段锁了？

**锚点**：`ConcurrentHashMap.java` 源码 / 1.7 与 1.8 源码对比

- [ ] **及格**：说出演进——1.7 用 **Segment 分段锁**（Segment 继承 ReentrantLock，默认 16 段）；1.8 改为 **CAS + synchronized**，只锁桶的头节点
- [ ] **良好**：及格 + 能解释为什么 1.8 更好——**锁粒度更细**（只锁单个桶，而不是一整段）、读操作**无锁**（`Node` 的 `val`/`next` 用 volatile）、`synchronized` 不重是因为有**锁升级**（无锁→偏向→轻量→重量，无竞争时开销极小）
- [ ] **精通**：良好 + 能应对追问——size 统计怎么做到并发（`CounterCell` 分散计数，无锁求和）、扩容协助（`transfer` 多线程帮忙搬数据）、`TreeBin` 对树根加写锁、`ForwardingNode` 的作用

## 5. `fail-fast` 机制是什么？

- [ ] **及格**：遍历集合时，如果结构被修改（增删元素），**立即抛 `ConcurrentModificationException`**，而不是继续遍历
