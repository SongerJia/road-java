## GC算法
三大基础算法->分代收集理论->三色标记->并发标记问题->增量更新vsSATB->面试高频题
### 三大基础算法
#### 标记-清除（Mark-Sweep）
```
// 原理：
// ① 标记：从 GC Roots 出发，标记所有可达对象
// ② 清除：遍历堆，回收所有未标记的对象

// 优点：
// 实现简单，不需要移动对象

// 缺点：
// ① 产生内存碎片（不连续的空闲空间）
// ② 碎片多时，大对象分配困难
// ③ 标记和清除都要全堆扫描，效率低

// 内存状态：
// 标记后： [存活][存活][垃圾][存活][垃圾][存活]
// 清除后： [存活][存活][ 空 ][存活][ 空 ][存活]  ← 碎片！
```
#### 标记-复制（Mark-Copy）
```
// 原理：
// ① 把内存分成两块（from 和 to）
// ② 标记存活对象
// ③ 把存活对象复制到 to 区
// ④ 清空 from 区，交换身份

// 优点：
// ① 没有碎片（复制后内存连续）
// ② 分配简单（指针碰撞）
// ③ 存活对象少时效率高（只复制存活对象）

// 缺点：
// ① 浪费一半空间（永远有一块空着）
// ② 存活对象多时开销大（全复制）

// 应用：新生代回收（存活率低，适合复制）
// Eden:S0:S1 = 8:1:1，只浪费 10% 空间
```
#### 标记整理（Mark-Compact）
```
// 原理：
// ① 标记：和标记-清除一样
// ② 整理：存活对象向一端移动（紧凑排列）
// ③ 清理边界外的内存

// 优点：
// ① 没有碎片（对象紧凑排列）
// ② 不会浪费空间（不像复制要一半）
// ③ 分配简单（指针碰撞）

// 缺点：
// ① 移动对象开销大
// ② 需要更新所有引用（引用地址变了）
// ③ 需要 Stop-The-World

// 应用：老年代回收（存活率高，不适合复制）
```
三大算法对比

|对比|标记-清除|标记-复制|标记-整理|
|---|---|---|---|
|**空间**|有碎片|浪费一半|无碎片|
|**速度**|中|快（存活少时）|慢（移动对象）|
|**移动对象**|否|是|是|
|**内存连续**|否|是|是|
|**适用**|老年代（CMS）|新生代|老年代（Parallel）|
### 分代收集理论
为什么分代？
```
// 经验观察（弱分代假说）：
// ① 绝大多数对象"朝生夕灭"（立刻死亡）
// ② 少数对象长期存活

// 推论（强分代假说）：
// 存活越久的对象，越难被回收

// 基于此：
// 新生代：用复制算法（存活少，复制快）
// 老年代：用标记-整理（存活多，移动慢但值得）

// 跨代引用假说：
// 老年代引用新生代的对象很少（跨代引用少）
// 所以：用记忆集（Remembered Set）记录老年代对新生代的引用
// 新生代 GC 时不用扫描整个老年代
```
记忆集（Remembered Set）
```
// 问题：Minor GC 时，老年代对象可能引用新生代对象
// 这些引用也是 GC Roots 的一部分
// 难道要扫描整个老年代？太慢！

// 解决：记忆集
// 老年代中"引用新生代对象"的区域记录在记忆集中
// Minor GC 时，只用扫描记忆集记录的区域

// 写屏障（Write Barrier）：
// 老年代对象引用新生代对象时（赋值时），记录到记忆集
// 开销很小（只在赋值时）
```
### 三色标记（并发标记核心）
为什么需要三色标记？
```
// 问题：并发标记时（标记线程和业务线程同时运行）
// 业务线程可能修改引用关系
// 简单的"标记/未标记"两色无法处理并发修改

// 解决：三色标记法
```
三色状态
```
// 白色（White）：未被访问过 —— 可能被回收
// 灰色（Gray）：正在访问，但其引用还没处理完 —— 中间态
// 黑色（Black）：自己和引用都已处理完 —— 存活，不会被回收

// 过程：
// ① 初始：所有对象都是白色
// ② 从 GC Roots 开始访问 → 变灰色
// ③ 处理灰色对象的引用 → 引用对象变灰色，自己变黑色
// ④ 重复直到没有灰色
// ⑤ 剩下的白色对象 → 垃圾
```
标记过程图
```
初始：全部白色
[白][白][白][白][白][白]

开始标记：
GC Root → A（灰）
        → B（灰）

处理 A 的引用 → C（灰），A（黑）
处理 B 的引用 → D（灰），B（黑）
处理 C 的引用 → 无，C（黑）
处理 D 的引用 → E（灰），D（黑）
处理 E 的引用 → 无，E（黑）

结束：没有灰色了
[黑][黑][黑][黑][黑][白]  ← 白色 F 被回收
```
并发标记的问题
```
// 并发标记时，业务线程可能：
// ① 把已标记为黑色的对象，重新引用到白色对象
// ② 把灰色对象引用断开

// 两种致命错误：   打标记的是不回收
// ① 误标（把垃圾标成存活）→ 漏回收（下次 GC 再说，可接受）
// ② 漏标（把存活标成垃圾）→ 误回收（对象被错误回收，致命！）

// 并发标记必须保证不"漏标"   不少打标记，不打标记就是垃圾
```
### 解决漏标的两种方案
#### 方案一：增量更新（CMS采用）
```
// 思路：记录"新增引用"
// 当黑色对象新增了对白色对象的引用时
// 把黑色对象重新标记为灰色（让它在重新扫描时处理）

// 例子：
// A（黑）新增引用 → X（白）
// 记录：A 变成灰色，重新扫描 A 的引用
// 扫描时发现 X → X 变灰 → 存活 ✅

// 特点：
// 记录的是"引用变化"（新增引用）
// 简单，但重新标记时要扫描更多对象

// 漏标场景：黑色对象新增白色引用 → 增量更新记录 → 不丢失
```
#### 方案二：原始快照（SATB  G1采用）
```
// SATB（Snapshot At The Beginning）：起始快照
// 思路：记录"删除的引用"
// 标记开始时，记录当时的引用关系快照
// 如果某个引用在标记期间被删除
// 被删除引用的对象仍然按快照视为存活

// 例子：
// 标记开始时：B → X（快照记录了）
// 标记期间：B 删除了对 X 的引用
// 但快照中 X 还是存活的 → X 不会被回收 ✅

// 特点：
// 记录的是"引用删除"（旧引用）
// 可能误标（把垃圾当存活）→ 下次 GC 回收，可接受

// 面试记忆：
// CMS 用"增量更新"：记新增引用，黑变灰重扫
// G1 用"SATB"：记删除引用，按快照保留
```
对比总结

| 对比        | 增量更新（CMS） | 原始快照 SATB（G1） |
| --------- | --------- | ------------- |
| **记录**    | 新增的引用     | 删除的引用         |
| **重新标记**  | 黑色变灰色重扫   | 按快照保留         |
| **误回收风险** | 低（记录新引用）  | 低（保留旧引用）      |
| **误标风险**  | 低         | 高（可能多保留垃圾）    |
| **性能**    | 重新扫描多     | 记录删除操作        |
### GC完整流程（CMS为例）
```
// CMS 的 4 个阶段：
// ① 初始标记（STW）：标记 GC Roots 直接可达的对象
//    停顿很短（只扫根）

// ② 并发标记：从初始标记的对象出发，标记所有可达对象
//    和业务线程并发执行（不 STW）
//    用三色标记 + 增量更新

// ③ 重新标记（STW）：修正并发期间变化的引用
//    停顿较短（只重扫变化的部分）

// ④ 并发清除：清除垃圾对象
//    和业务线程并发执行（不 STW）
//    用标记-清除（产生碎片，CMS 的缺点）

// 总停顿 = 初始标记（短）+ 重新标记（短）
// 大部分时间并发 → 停顿小
```
### 面试高频题
#### 题目1：三大GC算法？各自特定？
```
// 标记-清除：简单，有碎片
// 标记-复制：无碎片，浪费一半空间，适合新生代
// 标记-整理：无碎片，移动对象开销大，适合老年代
```
#### 题目2：什么是三色标记？
```
// 白：未访问（可能回收）
// 灰：访问中（引用未处理完）
// 黑：处理完（存活）
// 遍历后剩下的白色对象 → 垃圾
```
#### 题目3：三色标记会漏标吗，怎么处理
```
// 会！黑色对象新增白色引用时可能漏标（误回收）
// 解决：
// CMS 增量更新：记录新增引用，黑变灰重扫
// G1 SATB：记录删除引用，按起始快照保留
```
#### 题目4：什么是stop the world?
```
// STW：GC 时暂停所有业务线程
// 为什么需要：防止标记过程中引用关系被修改（无法保证一致性）
// 影响：停顿越短越好 → 各种低延迟 GC（G1、ZGC）
```
#### 题目5：为什么新生代用复制，老年代用整理？
```
// 新生代存活率低：复制成本低（只复制少量存活对象）
// 老年代存活率高：复制要复制大量对象，不如移动整理
// 这是分代收集的核心
```
