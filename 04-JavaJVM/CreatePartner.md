## 对象创建与分配
对象创建流程->对象内存布局->对象头详解->分配内存方式->TLAB->栈上分配与逃逸分析->内存分配策略->面试高频题
### 对象创建流程
```
// new 一个对象的完整过程
User user = new User();
```
五步流程
```
// ① 类加载检查
// 检查常量池中能否找到 User 的符号引用
// 检查 User 是否已加载、解析、初始化
// 没有 → 先执行类加载（D1 的内容）

// ② 分配内存
// 对象所需内存大小在类加载后确定
// 在堆中分配一块连续内存

// ③ 初始化零值
// 分配的内存都置为零值
// int → 0，boolean → false，引用 → null
// 所以 Java 字段有默认值（不像 C++）

// ④ 设置对象头
// 设置 Mark Word（锁状态、hashCode、GC年龄）
// 设置类型指针（指向类元信息）
// 数组还要设置长度

// ⑤ 执行 init 方法
// 调用构造器，按代码执行初始化
// 此时对象才真正"创建完成"
```
与汇编层的对比
```
// Java 层面：
User user = new User("张三", 25);

// 字节码层面：
// new User              → 分配内存 + 零值
// dup                  → 复制引用
// ldc "张三"            → 加载参数
// bipush 25
// invokespecial <init>  → 调用构造器
// astore_1             → 赋值给变量
```
### 对象内存布局
```
三个部分
一个 Java 对象在内存中的布局：

┌──────────────────────────────┐
│        对象头（Header）        │  ← 8~16 字节
│  ├── Mark Word（标记字）       │    8 字节（64 位）
│  ├── 类型指针（Klass Pointer） │    4~8 字节
│  └── 数组长度（只有数组有）     │    4 字节
├──────────────────────────────┤
│        实例数据（Instance Data）│  ← 字段的实际值
│  按字段声明的顺序排列           │
├──────────────────────────────┤
│        对齐填充（Padding）      │  ← 保证 8 字节对齐
└──────────────────────────────┘
```
空对象占多少内存？
```
// Object obj = new Object();
// 64 位 JVM，压缩指针开启：
// 对象头：12 字节（Mark Word 8 + Klass Pointer 4）
// 对齐填充：4 字节
// 总共：16 字节！

// 所以一个空 Object 占 16 字节
// 100 万个空对象 = 16MB！
```
实例数据排列规则
```
// 字段排列规则：
// ① 相同宽度的字段排在一起
// ② 父类字段在前，子类字段在后
// ③ 规则可调（-XX:FieldsAllocationStyle）

public class User {
    int id;        // 4 字节
    boolean vip;   // 1 字节
    String name;   // 4 字节（压缩指针）
    long createTime; // 8 字节
}

// 排列：long(8) + int(4) + String(4) + boolean(1) + 对齐
// 长类型优先对齐到 8 字节边界
```
### 对象头详解
Mark Word 存储内容
```
┌────────────────────────────────────────────────┐
│ Mark Word（8 字节）                              │
│  无锁：hashCode(31) + 分代年龄(4) + 偏向标志(1) + 锁标志(2) │
│  偏向锁：线程ID(54) + epoch(2) + 年龄(4) + 偏向(1) + 锁标志(2) │
│  轻量锁：指向栈中锁记录的指针                      │
│  重量锁：指向 monitor 的指针                      │
│  GC：转发指针（对象移动后的新地址）                 │
└────────────────────────────────────────────────┘
```
Mark Word 动态性
```
// Mark Word 不是固定的！
// 根据对象状态动态变化：
// ① 新建：无锁状态（存 hashCode、GC 年龄）
// ② 加锁：存储锁信息（覆盖 hashCode）
// ③ GC 标记：存储转发指针

// 注意：
// ① System.identityHashCode() 返回的是 identity hash
//    与是否重写 hashCode() 无关
// ② identity hash 只会计算一次，之后缓存
//    加锁时只是“挪走”，不会重新计算
// ③ 调用过 identityHashCode / Object.hashCode()
//   （偏向锁需要存线程 ID，和 hashCode 冲突）
```
### 分配内存方式
两种分配方式
```
// ① 指针碰撞（Bump the Pointer）
// 堆内存规整（用复制/整理算法）时
// 只需要移动指针即可分配

// 内存：[已使用 | 空闲]
//                 ↑ 指针在这里
// 分配：指针向后移动 size 即可

// ② 空闲列表（Free List）
// 堆内存不规整（用标记-清除算法）时
// 维护一个空闲列表，分配时找合适大小的块

// 内存：[已用][空闲][已用][空闲][已用]
// 分配：从空闲列表中找一块

// 用哪种取决于：GC 是否整理内存
// Serial/ParNew（复制算法）→ 指针碰撞
// CMS（标记-清除）→ 空闲列表
```
并发分配的安全问题
```
// 问题：多线程同时分配内存 → 指针碰撞会冲突

// 方案一：CAS + 失败重试（乐观锁）
// 失败就重试

// 方案二：TLAB（本地线程分配缓冲）
// 每个线程在 Eden 区预分配一块私有空间
// 在自己的 TLAB 中分配，不需要同步
// TLAB 用完了才需要 CAS 分配新 TLAB
```
### TLAB（线程本地分配缓冲）
什么是TLAB
```
// TLAB（Thread Local Allocation Buffer）：
// 每个线程在 Eden 区预留的一块私有空间
// 对象优先在自己的 TLAB 中分配 → 无竞争

// 参数：
// -XX:+UseTLAB：开启（默认开启）
// -XX:TLABSize：TLAB 大小
// -XX:TLABWasteTargetPercent：允许浪费的比例

// 流程：
// ① 线程启动 → 在 Eden 分配一块 TLAB
// ② 新对象 → 在自己的 TLAB 中分配（无竞争）
// ③ TLAB 快用完 → 申请新的 TLAB（CAS）
// ④ 大对象 > TLAB → 直接在 Eden 分配
```
结构
```
Eden 区：
┌──────────────────────────────────────────────────┐
│  TLAB(线程1) │ TLAB(线程2) │ TLAB(线程3) │ 共享区域 │
└──────────────────────────────────────────────────┘
     ↑             ↑             ↑
  线程1独享      线程2独享      线程3独享    （竞争区）
  无竞争         无竞争         无竞争
```
### 栈上分配与逃逸分析
逃逸分析（Escape Analysis）
```
// 逃逸分析：JIT 编译器分析对象的作用域
// 判断对象是否"逃逸"出方法

// ① 不逃逸：对象只在方法内使用 → 栈上分配
// ② 方法逃逸：对象被方法返回/作为参数传递
// ③ 线程逃逸：对象被其他线程访问

public class EscapeAnalysis {
    // ❌ 逃逸：对象被返回
    public User createUser() {
        User user = new User();  // 逃逸了（被返回）
        return user;
    }

    // ✅ 不逃逸：对象只在方法内用
    public long sum() {
        Point p = new Point(1, 2);  // 不逃逸（方法内使用）
        return p.x + p.y;
    }
    // p 可以栈上分配，方法结束自动销毁
}
```
三大优化（基于逃逸分析）
```
// 优化一：栈上分配
// 不逃逸的对象 → 栈上分配（不进入堆）
// 方法结束自动销毁，无需 GC

// 优化二：标量替换
// 不逃逸的对象 → 拆散成基本类型
public long sum() {
    // Point p = new Point(1, 2); → 拆成 x=1, y=2 两个局部变量
    return x + y;  // 没有 Point 对象了！
}
// 对象的字段被替换成独立的局部变量（标量）

// 优化三：锁消除
// 不逃逸的对象加锁 → 锁没用（其他线程访问不到）→ 消除锁
public void append(String a, String b) {
    StringBuffer sb = new StringBuffer();  // 局部变量，不逃逸
    sb.append(a);   // synchronized 被消除
    sb.append(b);
}
```
参数
```
// 逃逸分析参数（JDK 6u23+ 默认开启）：
// -XX:+DoEscapeAnalysis：开启逃逸分析
// -XX:+EliminateAllocations：标量替换
// -XX:+EliminateLocks：锁消除
// -XX:+PrintEscapeAnalysis：打印分析结果
```
### 面试高频

> **Q:** "什么是逃逸分析？三大优化是什么？" 
> **A:** "JIT 编译器分析对象是否逃逸出方法。不逃逸的对象可以做三个优化：① 栈上分配（不进堆，免 GC）；② 标量替换（对象拆成基本类型变量）；③ 锁消除（锁没有竞争者就删掉）。"
### 内存分配策略
对象分配总流程
```
new 对象
    │
    ├── 逃逸分析：不逃逸 → 栈上分配（标量替换）✅ 免 GC
    │
    ├── 进入 Eden 的 TLAB 分配（无竞争）
    │   ├── TLAB 不够 → CAS 申请分配新的 TLAB
    │   └── 大对象（>TLAB）→ 跳过TLAB，直接在 Eden 分配
    │
    ├── Eden 满 → Minor GC
    │   ├── 存活对象 → S0 → S1（复制）
    │   ├── 年龄 +1
    │   └── 年龄 ≥ 15 → 老年代
    │
    ├── 大对象（>PretenureSizeThreshold）→ 直接进老年代
    │
    └── 老年代满 → Major GC / Full GC
```
大对象直接进老年代
```
// 为什么大对象直接进老年代？
// 大对象在新生代复制时开销大（复制成本高）
// 直接放老年代，避免反复复制

// 参数：-XX:PretenureSizeThreshold=1M
// 超过 1MB 的对象直接进老年代

// 注意：这个参数只对 Serial/ParNew 有效
// G1 不适用
```

#### 题目2：对象在内存中占用多少？怎么算？
```
// 对象头（8~16）+ 实例数据（字段）+ 对齐填充（8 的倍数）

// 空 Object：16 字节（12 头 + 4 填充）
// 含 int 字段：16 字节（12 + 4，无需填充）
// 含 long 字段：24 字节（12 + 8 + 4 填充）
```
#### 题目3：对象一定在堆上分配吗？
```
// 不一定！
// 逃逸分析后不逃逸的对象 → 栈上分配（或标量替换）
// 所以"所有对象都在堆上"是不准确的
// HotSpot 开启了逃逸分析后，部分对象在栈上
```
#### 题目4：TLAB是什么？解决了什么问题？
```
// 线程本地分配缓冲
// 解决多线程并发分配内存的竞争问题
// 每个线程在 Eden 预分配私有空间，无锁分配
```
题目5：指针碰撞和空闲列表的区别？
```
// 堆内存规整（复制/整理 GC）→ 指针碰撞（移动指针）
// 堆内存不规整（标记-清除 GC）→ 空闲列表（找合适块）
```
