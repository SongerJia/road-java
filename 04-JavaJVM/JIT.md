## JIT编译与执行引擎
执行方式->解释器vsJIT->JIT编译器->分层编译->热点探测->JIT优化->OSR->面试高频题
### 执行方式
两种执行方式
```
// Java 代码的执行流程：
// 源码 .java → 编译器 → 字节码 .class → JVM 执行

// JVM 执行字节码有两种方式：
// ① 解释执行：逐条翻译字节码为机器码执行
// ② 编译执行（JIT）：把字节码编译成机器码后直接执行

// 谁执行？
// 执行引擎（Execution Engine）
```
执行引擎流程
```
.java 源码
    ↓ javac 编译
.class 字节码
    ↓ 类加载器加载
方法区的字节码
    ↓ 执行引擎
两种方式：
    ├── 解释器（Interpreter）—— 逐条解释执行（慢）
    └── JIT 编译器 —— 编译成机器码执行（快）
```
### 解释器vsJIT
解释器（Interpreter）
```
// 特点：逐条翻译字节码为机器码，执行一条翻译一条
// 优点：启动快（不需要等待编译）
// 缺点：运行慢（每条指令都要翻译）

// 场景：程序启动阶段、冷代码（不常用代码）
```
JIT编译器（Just In Time）
```
// 特点：把热点代码编译成机器码，直接执行
// 优点：运行快（机器码直接执行）
// 缺点：编译需要时间（启动慢）

// 场景：运行一段时间后的热点代码
```
两者配合
```
// HotSpot 的策略：两者配合
// ① 启动阶段：先解释执行（快速启动）
// ② 运行中：发现热点代码 → JIT 编译成机器码
// ③ 后续执行：直接用机器码（快）

// 这就是"混合模式"（Mixed Mode）
// java -Xint：纯解释模式（慢）
// java -Xcomp：纯编译模式（启动慢）
// 默认：混合模式

// 参数：-XX:+TieredCompilation 分层编译（JDK 8+ 默认开启）
```
对比总结

|对比|解释器|JIT 编译器|
|---|---|---|
|**执行方式**|逐条翻译|整体编译成机器码|
|**启动速度**|快|慢（需要编译）|
|**运行速度**|慢|快（机器码）|
|**内存**|少|多（存机器码）|
|**适用**|冷代码、启动期|热点代码|
### JIT编译器
两种JIT编译器
```
// ① C1 编译器（Client Compiler）
// 特点：编译快，优化少
// 适用：客户端应用（响应快）
// 之前叫 Client 编译器

// ② C2 编译器（Server Compiler）
// 特点：编译慢，优化多（深度优化）
// 适用：服务端应用（运行快）
// 之前叫 Server 编译器

// 参数：
// -client：用 C1
// -server：用 C2
// -XX:+TieredCompilation：分层编译（都用）
```
C1 vs C2

|对比|C1|C2|
|---|---|---|
|**编译速度**|快|慢|
|**优化程度**|低（基本优化）|高（深度优化）|
|**执行效率**|中|高|
|**适用**|客户端|服务端|
|**默认**|JDK 8 分层后都启用||
C2的深度优化
```
// C2 能做的优化：
// ① 逃逸分析→ 栈上分配、标量替换、锁消除
// ② 方法内联（Inline）—— 最重要！
// ③ 公共子表达式消除
// ④ 循环展开
// ⑤ 空指针检查消除
// ⑥ 数组边界检查消除

// 参数：
// -XX:MaxInlineSize=325：内联的方法大小上限
// -XX:FreqInlineSize=325：热点方法内联上限
```
### 方法内联
什么是内联？
```
// 把方法调用"展开"成方法体，避免调用开销

// 原始代码：
public int add(int a, int b) {
    return a + b;
}

public int compute() {
    int result = add(1, 2);  // 调用 add
    return result;
}

// 内联后（JIT 自动优化）：
public int compute() {
    int result = 1 + 2;  // 直接把 add 的方法体展开
    return result;
}
// 没有方法调用开销了！
```
内联的收益
```
// 方法调用开销：
// ① 创建栈帧
// ② 参数传递
// ③ 跳转指令
// ④ 返回处理

// 内联后这些都没了
// 所以 getter/setter 用内联后几乎没有开销
// （呼应封装的 JIT 内联优化）

// 哪些方法会被内联？
// ① 方法体小（< MaxInlineSize）
// ② 热点方法（被频繁调用）
// ③ 非多态方法（能确定具体实现）
```
为什么多态方法难内联？
```
// 多态调用：编译时不知道调哪个实现
public void process(Animal animal) {
    animal.sound();  // 可能是 Dog 或 Cat → 不知道内联谁
}

// 解决方案：内联缓存（Inline Cache）
// ① 第一次调用：记录实际类型（如 Dog）
// ② 后续调用：如果还是 Dog → 直接内联 Dog.sound
// ③ 如果类型变了（出现 Cat）→ 缓存失效，重新记录

// 所以：单态调用点（Monomorphic）才能稳定内联
// 这也是为什么"面向接口编程"太多层会降低性能（多态难优化）
```
### 热点探测
什么是热点代码？
```
// 被频繁执行的代码 → 热点 → JIT 编译
// HotSpot 的名字就来自"热点探测"
```
探测方式
```
// 方法调用计数器（Method Invocation Counter）
// 统计方法被调用的次数
// 达到阈值 → 触发 C1 编译

// 回边计数器（Back Edge Counter）
// 统计循环执行的次数
// 循环达到阈值 → 触发 OSR 编译

// 参数：
// -XX:CompileThreshold=10000：方法调用次数阈值（C1 默认 1500，C2 默认 10000）
// -XX:OnStackReplacePercentage
```
反优化（Deoptimization）
```
// 情况：编译后的假设被打破 → 退回解释执行

// 例子：
// ① 内联缓存假设"只有 Dog" → 突然来了 Cat → 反优化
// ② 逃逸分析假设"不逃逸" → 反射访问 → 反优化

// 反优化：把执行流退回解释器，重新优化
// 这是 JIT 的自适应机制
```
### OSR（栈上替换）
什么是OSR
```
// OSR（On-Stack Replacement，栈上替换）
// 长循环场景：循环还没执行完，但触发编译
// 编译完成后，不退出方法，直接在栈上替换为机器码

// 场景：
public long sum(int n) {
    long total = 0;
    for (int i = 0; i < n; i++) {   // 长循环
        total += i;                 // 循环体执行很多次
    }                                // 触发回边计数 → OSR
    return total;
}

// 没有 OSR：必须等循环结束（方法返回）才能用编译代码
// 有 OSR：循环中途切换为机器码执行
```
为什么需要OSR
```
// 长循环（如 for 循环 10 亿次）：
// 如果等循环结束再编译 → 前面都在解释执行 → 太慢
// OSR 在循环执行中替换为机器码 → 后面循环用机器码 → 快
```
### JVM版本与JIT的演进
```
// JDK 8：C1 + C2（分层编译）
// JDK 9+：引入 Graal JIT（可选实验）
// JDK 15+：Graal JIT 正式（-XX:+UseJVMCICompiler 可选）
// JDK 17+：AOT（提前编译）实验

// 默认还是 C1+C2
// Graal：新一代 JIT，优化更好（尤其对新技术友好）
```
### 面试高频题
#### 题目1：解释器和JIT的区别？
```
// 解释器：逐条翻译，启动快运行慢
// JIT：编译成机器码，启动慢运行快
// 配合：先解释后编译（混合模式）
```
#### 题目2：什么是JIT?为什么需要它？
```
// 即时编译：运行时把热点字节码编译成机器码
// 需要它：解释执行太慢，编译执行启动慢
// 折中：混合模式，兼顾启动速度和运行性能
```
#### 题目3：C1和C2的区别？
```
// C1：编译快优化少（客户端）
// C2：编译慢优化深（服务端）
// 分层编译：先 C1 快速编译，再 C2 深度优化
```
#### 题目4：什么是热点探测
```
// 方法调用计数器 + 回边计数器
// 达到阈值 → JIT 编译
```
#### 题目5：什么是方法内联？
```
// 展开方法调用，避免调用开销
// getter 内联后几乎零开销
// 多态难内联，用内联缓存
```
#### 题目6：什么是OSR
```
// 栈上替换：长循环中途切换为机器码
// 不用等方法结束
```
#### 题目7：JVM怎么执行代码
```
// 先解释执行（快速启动），热点代码通过 JIT 编译成机器码
// （方法调用计数+回边计数），C1 快速编译、C2 深度优化（分层编译），
// 长循环用 OSR 栈上替换，主要优化有方法内联、逃逸分析等。
```
