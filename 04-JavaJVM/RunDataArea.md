### 内存区域总览
```
JVM运行时内存划分
  JVM 内存
        ┌───────────────────────────┐
        │       线程共享区            │
        │  ┌─────────┐ ┌─────────┐  │
        │  │   堆     │ │ 方法区   │  │
        │  │ (Heap)  │ │(MetaSpace)│ │
        │  └─────────┘ └─────────┘  │
        ├───────────────────────────┤
        │       线程私有区            │
        │  ┌──────┐ ┌──────┐ ┌────┐ │
        │  │虚拟机栈│ │本地方法│ │ PC │ │
        │  │ (Stack)│ │ 栈   │ │    │ │
        │  └──────┘ └──────┘ └────┘ │
        └───────────────────────────┘
```

| 区域      | 共享性 | 异常                 | 作用            |
| ------- | --- | ------------------ | ------------- |
| 堆       | 共享  | OutOfMemoryError   | 存放对象实例        |
| 方法区/元空间 | 共享  | OutOfMemoryError   | 类信息、常量、静态常量   |
| 虚拟机栈    | 私有  | StackOverflowError | 方法调用的栈帧       |
| 本地方法栈   | 私有  | StackOverflowError | 本地方法调用        |
| 程序计数器   | 私有  | 无异常                | 当前执行的字节码行号    |
| 直接内存    | 共享  | OutOfMemoryError   | NIO直接缓冲区（不在堆） |

### 线程私有区
#### 程序计数器 （PC Register）
```
// 作用：记录当前线程正在执行的字节码指令地址
// 特点：
// ① 线程私有 —— 每个线程一个
// ② 唯一不会 OOM 的区域
// ③ 唯一规范中没有规定任何 OutOfMemoryError 的区域

// 为什么需要？
// 多线程切换后，需要恢复"上次执行到哪"
// 每个线程独立的 PC，切换线程时保存/恢复

// 执行 native 方法时 PC 为 undefined
```
#### 虚拟机栈（VM Stack）
```
// 作用：方法调用的内存模型
// 每个方法调用 → 创建一个栈帧（Stack Frame）
// 方法结束 → 栈帧弹出

// 栈帧包含：
// ① 局部变量表 —— 基本类型、对象引用、returnAddress
// ② 操作数栈 —— 计算时的临时操作数
// ③ 动态链接 —— 指向运行时常量池的引用
// ④ 方法返回地址 —— 调用者的下一条指令
// ⑤ 附加信息

public void a() {
    b();  // a 的栈帧入栈
}

public void b() {
    c();  // b 的栈帧入栈
}

// 调用栈：
// | c 的栈帧 |   ← 栈顶（正在执行）
// | b 的栈帧 |
// | a 的栈帧 |
// | main 的栈帧 |
// └─────────┘

// 异常：
// 栈深度超过 JVM 限制 → StackOverflowError
// 递归无限 → StackOverflowError
```
#### 本地方法栈（Native Method Stack）
```
// 作用：为 native 方法（C/C++ 实现）服务
// 和虚拟机栈类似，只是服务对象不同

// HotSpot 把本地方法栈和虚拟机栈合二为一
// 所以 HotSpot 中看不到单独的本地方法栈区域

// 异常：
// 栈溢出 → StackOverflowError
// 内存不足 → OutOfMemoryError
```
#### 栈上分配
```
// 面试关联：逃逸分析 + 栈上分配
// 如果对象不会逃逸出方法 → 可以在栈上分配
// 方法结束自动销毁，不需要 GC
// 减少 GC 压力
```
### 线程共享区
#### 堆（Heap）
```
// 作用：存放对象实例（几乎所有对象）
// 特点：
// ① 线程共享
// ② JVM 管理的最大内存区域
// ③ GC 的主要战场

// 参数：
// -Xms：初始堆大小
// -Xmx：最大堆大小（默认物理内存 1/4）
// -Xmn：新生代大小
// -XX:MaxMetaspaceSize：元空间上限

// 结构（分代）：
// 堆
// ├── 新生代（Young）
// │   ├── Eden 区（8/10）
// │   ├── S0 幸存区（1/10）
// │   └── S1 幸存区（1/10）
// └── 老年代（Old）

// 异常：堆溢出 → OutOfMemoryError: Java heap space
```
#### 方法区/元空间（Method Area/MetaSpace）
```
// 作用：存储类信息
// ① 类的结构信息（字段、方法、接口）
// ② 运行时常量池（编译期常量 + 运行期常量）
// ③ 静态变量（JDK 7 后移入堆）
// ④ 类加载器的引用

// JDK 版本演变：
// JDK 6：永久代（PermGen）—— 大小固定，容易 OOM
// JDK 7：永久代，字符串常量池移到堆
// JDK 8+：元空间（MetaSpace）—— 使用本地内存，默认无上限

// 为什么用元空间替换永久代？
// ① 永久代大小固定，容易 OOM（PermGen space）
// ② 元空间使用本地内存，不再 OOM（默认）
// ③ 更容易调优
// ④ 移除了字符串常量池（移到堆）

// 参数：
// -XX:MetaspaceSize：初始大小（默认约 21MB）
// -XX:MaxMetaspaceSize：最大大小（默认无限）
```
### 面试高频

> **Q:** "JDK 8 的方法区为什么叫元空间？和永久代什么区别？" 
> **A:** "JDK 8 用元空间替代永久代：① 元空间使用本地内存（默认无上限），永久代在 JVM 内存中大小固定容易 OOM；② 字符串常量池和静态变量移到堆；③ 减少 OOM 概率。"

> **Q:** "哪些数据会放到元空间？" 
> **A:** "类元信息、运行时常量池、方法信息、类加载器信息。对象的实例数据放堆，静态变量 JDK7+ 放堆，字符串常量池 JDK7+ 放堆。"
### 堆结构详解
分代结构
```
                   堆
┌────────────────────────────────────┐
│           新生代（Young）            │
│  ┌────────┬─────┬─────┐            │
│  │ Eden   │ S0  │ S1  │   老年代   │
│  │ (80%)  │(10%)│(10%)│  (Old)    │
│  └────────┴─────┴─────┘            │
│        8:1:1 比例                    │
└────────────────────────────────────┘
```
为什么分代？
```
// ① 大部分对象"朝生夕灭"（立即死亡）
// ② 少部分对象长期存活

// 分代的好处：
// 新生代：用复制算法，只回收少量存活对象，效率高
// 老年代：用标记-整理，处理存活率高的对象

// 如果不分代：所有对象一起 GC → 每次扫描全部 → 慢
```
对象的分配和晋升
```
// ① 新对象 → 优先分配在 Eden 区
// ② Eden 满 → Minor GC（新生代回收）
// ③ Minor GC 存活 → 进入 S0（复制算法）
// ④ 每次 Minor GC 存活 → 年龄 +1（age 存在对象头）
// ⑤ 年龄达到 15（默认）→ 晋升到老年代
// ⑥ 大对象（-XX:PretenureSizeThreshold）→ 直接进老年代

// 参数：
// -XX:MaxTenuringThreshold=15：晋升年龄阈值（默认 15）
// -XX:PretenureSizeThreshold：大对象直接进老年代的阈值
```
Minor GC、Major GC和 Full GC

| GC       | 作用范围 | 触发         |
| -------- | ---- | ---------- |
| Minor GC | 新生代  | Eden满      |
| Major GC | 老年代  | 老年代满       |
| Full GC  | 整个堆  | 老年代+各种触发条件 |
### 直接内存（Direct Memory）
```
// 定义：不是 JVM 管理的内存，是操作系统内存
// 通过 NIO 的 DirectByteBuffer 使用

// 为什么需要？
// 传统 IO：磁盘 → 内核缓冲区 → JVM 缓冲区 → 应用
// 直接内存：磁盘 → 直接内存 → 应用（少一次拷贝）
// NIO 零拷贝的基础

// 使用：
ByteBuffer buffer = ByteBuffer.allocateDirect(1024);  // 直接内存
ByteBuffer heapBuffer = ByteBuffer.allocate(1024);    // 堆内

// 特点：
// ① 不受 -Xmx 限制（但受物理内存限制）
// ② 分配/回收开销大
// ③ 适合大块数据的频繁 IO

// 异常：OutOfMemoryError: Direct buffer memory
// 排查：JVM 参数没设，但物理内存耗尽
```
### 各区域异常汇总

|区域|异常|典型场景|
|---|---|---|
|**堆**|OutOfMemoryError: Java heap space|对象太多，-Xmx 太小|
|**元空间**|OutOfMemoryError: Metaspace|动态生成类太多（反射/代理）|
|**虚拟机栈**|StackOverflowError|无限递归|
|**本地方法栈**|StackOverflowError|native 递归|
|**程序计数器**|无（唯一不 OOM）|—|
|**直接内存**|OutOfMemoryError: Direct buffer memory|NIO 缓冲区过大|
内存泄漏 VS 内存溢出
```
// 内存溢出（OOM）：内存真的不够了
// 内存泄漏（Leak）：对象无法回收，占着内存不放
// 泄漏是溢出的常见原因之一

// 常见泄漏场景：
// ① ThreadLocal 没 remove()
// ② 静态集合一直 add
// ③ 连接/流没关闭
// ④ 监听器没移除
```
### 面试高频题目
#### 题目1：JVM内存区域有哪些？
```
// 线程私有：程序计数器、虚拟机栈、本地方法栈
// 线程共享：堆、方法区（元空间）
// 另外：直接内存（不属于 JVM 管理）
```
#### 题目2：栈和堆的区别？
|对比|栈|堆|
|---|---|---|
|**存储**|局部变量、引用|对象实例|
|**生命周期**|方法结束销毁|GC 回收|
|**大小**|固定（小）|可配置（大）|
|**共享**|线程私有|线程共享|
|**速度**|快（栈指针）|慢（GC）|

```
// ① 年龄达到阈值（默认 15）的对象

// ④ 动态年龄判断：Survivor 中同年龄对象超过一半时
```
